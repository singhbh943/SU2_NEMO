## 1. Objective

The work hardened the existing SU2 NEMO solver rather than creating a
separate solver.

The objective was to retain the production SU2 architecture while
improving robustness and consistency for extreme-Mach,
thermochemical-nonequilibrium flows using Mutation++.

The primary demanding configuration used for validation was ionized
two-temperature AIR11 at Mach 23.9.

---

## 2. Thermochemical State Robustness

The NEMO conservative-to-primitive recovery path was hardened for
high-enthalpy states.

Implemented and validated behavior includes:

- thermochemical admissibility checking;
- accepted-state restoration;
- controlled retry/backtracking;
- fallback behavior for unsuccessful primitive recovery;
- species positivity protection;
- avoidance of contaminating the accepted state during failed trial
  recovery.

The accepted-state behavior preserves the previously validated ordering:
restore before retry and restore before fallback, without restoring
before the first ordinary candidate.

---

## 3. Backend-Aware Temperature Admissibility

The native SU2 thermochemical backend retains its original temperature
limits.

Mutation++ is no longer forced through the native fixed upper-temperature
limit where that restriction is not appropriate.

This prevents an artificial native-backend temperature ceiling from
being applied to Mutation++ high-temperature states.

Relevant SU2 commit:

`591799d967 Make NEMO temperature admissibility backend aware`

---

## 4. Mutation++ Ambipolar Stefan-Maxwell Transport

A Mutation++-specific Stefan-Maxwell transport path was added for
ionized NEMO mixtures.

Implemented features include:

- multicomponent Stefan-Maxwell diffusion;
- electron-containing mixtures;
- ambipolar closure;
- composition-gradient driving;
- barodiffusion contribution;
- two-temperature partial-pressure driving;
- species diffusion flux based on `-rho Y_s V_s`;
- energy diffusion including electron species;
- residual mass-flux roundoff correction;
- fallback to the legacy mixture-averaged transport path where the
  Mutation++ Stefan-Maxwell path is unavailable.

No explicit Soret contribution is claimed.

Recommended technical description:

> Mutation++ Stefan-Maxwell ambipolar closure with
> composition/barodiffusion/two-temperature partial-pressure driving,
> without explicit Soret diffusion.

Relevant SU2 commit:

`7d96e1560a Add Mutation++ ambipolar Stefan-Maxwell transport to NEMO`

## 5. Mutation++ Stefan-Maxwell Thread Safety

The Mutation++ Stefan-Maxwell implementation was corrected so
composition storage used during the solve is local rather than static.

This removes shared mutable Eigen state from that transport calculation.

Mutation++ history includes:

`70202b06c813e76c6bc98010cd7974ac853d11cf`
`Make Stefan-Maxwell transport thread safe`

## 6. Eigen Shared-Library Symbol Isolation

A runtime crash was traced to Eigen template symbol interposition between
the SU2 executable and the Mutation++ shared library.

The Mutation++ shared library was hardened using:

- `-fvisibility-inlines-hidden`
- `-Wl,-Bsymbolic-functions`

This ensures Mutation++ uses its own compatible Eigen template
instantiations.

Mutation++ implementation commit:

`c44160ef22ca9a9236ab2e10b8b9acb3ff7eefad`

Relevant SU2 integration commit:

`e65a903589 Prevent Mutation++ Eigen symbol interposition in NEMO`

## 7. Catalytic Wall Species Flux and Heat-Flux Reporting

Catalytic-wall heat reporting was corrected to use the actual species
viscous wall flux already generated by the boundary condition.

The reported species enthalpy contribution is therefore based on the
same wall-normal species flux used by the solver instead of reconstructing
a separate inconsistent quantity.

This also avoids the previously identified extra-area scaling error.

Relevant commit:

`65e20fc449 Use exact catalytic wall species flux in NEMO heat reporting`

---

## 8. Mutation++ Dimensional Support Contract

The current Mutation++ NEMO coupling passes dimensional
thermochemical/transport quantities directly between SU2 and Mutation++.

A complete nondimensional Mutation++ conversion layer is not currently
implemented for all thermodynamic, chemistry and transport quantities.

To prevent silent unit inconsistency, Mutation++ NEMO now requires:

`REF_DIMENSIONALIZATION = DIMENSIONAL`

Unsupported nondimensional modes fail explicitly.

Relevant commit:

`7b27e34dd7 Require dimensional NEMO runs with Mutation++`

## 9. Electronic and Electron Energy Audit

The Mutation++ vibrational/electronic energy source was audited.

For Mutation++, `energyTransferSource()` supplies the complete
Mutation++ energy-transfer source. Therefore an additional independent
electronic-energy source was not added to SU2, which would risk
double-counting.

Mutation++ source terms include the relevant electron-heavy,
chemistry-electron, electronic-energy, electron-impact and
vibrational/electronic transfer mechanisms according to the selected
Mutation++ model.

The generic native-NEMO comment stating that electronic energy is not
implemented does not justify adding a duplicate Mutation++ source.

## 10. AIR11 Pressure Jacobian Defect and Fix

A specific inconsistency was found in the Mutation++ AIR11 implicit
thermodynamic Jacobian.

The NEMO pressure model is

`p = sum_e rho_s R_s Tve + sum_h rho_s R_s T`

but Mutation++ AIR11 inherited the older generic
`CNEMOGas::ComputedPdU()` expression.

A conservative finite-difference regression demonstrated large errors in
the inherited pressure derivative while the corresponding temperature
derivatives remained accurate.

Observed pre-fix relative pressure-derivative errors were approximately
0.35-0.72 for affected conservative variables.

The fix:

- makes `CNEMOGas::ComputedPdU()` virtual;
- leaves the native CNEMOGas implementation body unchanged;
- adds a `CMutationTCLib::ComputedPdU()` override;
- constructs the pressure Jacobian directly using the pressure chain
  rule and the Mutation++-consistent `dT/dU` and `dTve/dU`;
- includes the direct species-density pressure contribution.

Final commit:

`5bdf389610 Make Mutation++ NEMO pressure Jacobian energy consistent`

## 15. Native Solver Preservation

The hardening work intentionally preserves the existing SU2 solver
architecture.

In particular:

- no separate replacement solver was introduced;
- native `CNEMOGas::ComputedPdU()` implementation body remains intact;
- Mutation++ specialization is isolated through the fluid-model
  interface;
- existing SU2 solver/numerics infrastructure remains in use;
- validated native behavior is not replaced merely to satisfy
  Mutation++ requirements.
